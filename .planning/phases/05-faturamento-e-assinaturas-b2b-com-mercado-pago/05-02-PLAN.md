# Plan 05-02: Webhooks do Mercado Pago, Carência/Suspensão de Tenant e Painéis de Faturamento

## Objective
Implementar o pipeline completo de conciliação de faturamento da Alvora: endpoint seguro de webhooks (`POST /api/webhooks/mercadopago`) com validação de assinatura HMAC `x-signature`, middleware de controle de acesso com janela de carência de 5 dias para inadimplência, componente Livewire de faturamento para o gestor de RH (`CompanyBilling`) e painel executivo global de faturamento para o Super Admin (`AdminBilling`).

## User Story
**As a** gestor de RH (`company_admin`),
**I want to** acompanhar o status da assinatura corporativa da minha empresa, visualizar a taxa de utilização de vagas e histórico de faturas pagas, além de ter 5 dias de tolerância caso haja falha temporária de pagamento,
**so that** o treinamento dos meus colaboradores não seja bruscamente interrompido e eu possa regularizar a pendência com facilidade.

**As a** super admin da Alvora (`admin_alvora`),
**I want to** monitorar a receita recorrente mensal (MRR) da plataforma, ver a distribuição de planos das empresas e auditar as notificações de webhook recebidas,
**so that** eu tenha controle gerencial e financeiro total sobre as contas B2B ativas.

<task id="05-02-01" type="tracer">
  <name>Endpoint Seguro de Webhooks com Validação Criptográfica x-signature</name>
  <action>
    Desenvolver `App\Http\Controllers\Api\MercadoPagoWebhookController`:
    - Rota `POST /api/webhooks/mercadopago` isenta de verificação CSRF.
    - Método `handle(Request $request)`:
      1. Extrair os headers `x-signature` e `x-request-id`, além de `data.id` dos parâmetros.
      2. Validar a assinatura HMAC-SHA256 utilizando `MERCADO_PAGO_WEBHOOK_SECRET` via `hash_equals`.
      3. Processar eventos de pagamento (`type == 'payment'` ou `action == 'payment.created'|'payment.updated'`): consulta a transação via `MercadoPagoService->getPayment($id)` para confirmar o status real (`approved`, `rejected`, etc.).
      4. Se `approved`: atualiza `Invoice` para `paid`, atualiza `Subscription` para `active`, remove `grace_period_ends_at`, define data de renovação para +30 dias e atualiza a `Company` (`status = 'active'`, `plan`, e ajusta `max_users` correspondente: 20 para Starter, 100 para Pro).
      5. Se `rejected`/`cancelled`: se a assinatura estiver ativa, ativa o modo de carência (`status = 'overdue'`, `grace_period_ends_at = now()->addDays(5)`).
      6. Trata eventos de preapproval (`subscription_preapproval`): atualiza o status da assinatura correspondente.
    Garantir idempotência: requisições com mesmo `mp_payment_id` e status já processado retornam HTTP 200 imediatamente sem duplicidade.
  </action>

  <action>
    Criar o middleware `App\Http\Middleware\CheckSubscriptionStatus`:
    - Verifica a empresa do usuário autenticado:
      - Se a empresa estiver com status `overdue` (em carência), mas a data atual for maior que `grace_period_ends_at`: atualiza automaticamente para `status = 'suspended'`.
